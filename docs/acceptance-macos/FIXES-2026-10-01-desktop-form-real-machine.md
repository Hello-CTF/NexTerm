# 桌面形态真机验收（第 9–13 轮修复首次在真实桌面上跑）

- 日期：2026-10-01
- 起因：用户要求「构建每个端在真机器测试吧」。
  本轮之前，第 9–13 轮的修复**只在编译层面**经过桌面形态（`cargo build --features desktop`），
  桌面二进制**从未真正运行过**。服务端形态由懒猫盒子那一路覆盖，桌面形态是空白。
- 结论：四条判据全部通过（§3），并**附带证实** AI 接管在桌面形态可端到端跑通（§4.5）。
  同时发现一处小瑕疵：一次失败会弹**两条**错误 toast（§5）。

## 二、方法：AX 真驱 + 窗口 ID 截图 + 进程计数

三条证据链，互相独立：

1. **DOM 级判据走 AX 树**（不是"看着对"）：对话框、选项文案、错误提示都是 DOM 节点，
   WebKit 会把它们暴露成 `AXApplicationAlertDialog` / `AXStaticText` / `AXButton`。
   整棵树 dump 下来做**字符串计数**，判据是"命中 N 次"而不是"我看到了"。
2. **视觉证据**走 `screencapture -x -o -l <windowid>`（按窗口号抓，不依赖坐标换算），
   落在本目录 `40-` ~ `43-` 四张图。
3. **进程级判据**走 `pgrep`：`docker logs -f` 的**真实进程数**，这是第 10 轮修复的核心断言。

驱动工具：`axdrive <pid> {dump,find,rect,press,click,settext,focus,frontmost}`
（编译命令在源文件头注释里；坐标一律是**绝对屏幕点**）。

## 四、证据细节

### 4.1 断言 ① — 关标签三选一

```
press 「打开本地终端」            → 新建标签「终端 1」，终端真实拿到 bash 提示符
click 1174,400（标签 × 中心）     → AX 元素数 105 → 112，多出 7 个
```

多出来的正是对话框，完整结构：

```
[ 100] AXGroup  AXApplicationAlertDialog  pos=1307,627 size=440x290
[ 101] AXStaticText  value: 关闭「终端 1」
[ 103] AXStaticText  value: 这个终端在服务端还在运行，要如何处理？
[ 104] AXButton  title: 后台继续运行 进程保留在服务端，之后可在「后台会话」里重新接管
[ 105] AXButton  title: 结束进程 停止这个终端里的进程并释放它
[ 106] AXButton  title: 取消
```

`press 取消` 之后：元素数回到 **105**、两个选项文案 **0 命中**、
`value: 终端 1` 仍 **2 命中**（标签栏 + 面板头）⇒ **取消不清标签**，与 `requestCloseTab` 的
`choice === null → 什么都不做` 一致。

截图：`40-desktop-close-tab-choice.png`（主选项「后台继续运行」带主色边框，危险项「结束进程」是红字）。

### 4.2 断言 ② — 徽章不该出现（带正向对照）

判据不能只是"没搜到"——那可能是**功能根本没打进包**。所以做了正向对照：

| 检查 | 期望 | 实测 |
|---|---|---|
| 整棵 AX 树搜 `个设备正在观看` | 0 | **0** ✓ |
| 产物 `dist/assets/index-CJoMiNwt.js` 搜同一字面量 | ≥1 | **命中**（代码确实在包里）✓ |

⇒ 缺席是**渲染条件为假**的结果，不是功能缺失。
机制上：桌面形态 `SubscriberKey` 恒返回字面量 `"desktop"`，订阅数上限为 1，
而徽章的渲染条件是 `subscribers > 1`。

### 4.3 断言 ③ — Docker 日志跟随的 PTY 归零

这是第 10 轮修复在**桌面形态**的首次真机验证。

| 步骤 | `docker logs -f` 进程数 |
|---|---|
| 基线（面板未开） | **0** |
| `press 「查看日志」` 之后 | **1** — `docker logs -f --tail 500 0a77c07e76b6` |
| `press 「返回」` 之后（等 3s） | **0** |

- 日志视图本身也确认退出：AX 元素数 413 → 183，「日志跟随 / 跟随中」0 命中。
- 日志视图里确实有真实输出（`[bin] 容器架构 arm64，目标 x86_64-unknown-linux-gnu`），
  不是空壳。截图：`41-desktop-docker-log-follow.png`。
- 一个附带观察：`press 「查看日志」` **命中了 2 个 AX 元素**（列表渲染出了两份同构节点），
  但只起了 **1 个** PTY ⇒ 组件里的 in-flight 去重确实挡住了重复发起。
- 注意桌面形态走的是**前端清理**（`attached` 失效 → `terminalApi.closeTab(tabId, "kill")`），
  **不是**服务端那条 5s 宽限回收 —— `ephemeral` 标记在桌面上没有消费者。两条路径都对，但不是同一条。

## 五、本轮唯一发现的瑕疵

**一次失败弹两条错误 toast**：内容基本重复，一条是提供方原始错误、一条是包装后的

## 六、方法学坑（下次别再踩）

1. **WebKit 的 AX 树是延迟出现的。** 刚设完 `AXEnhancedUserInterface` 立刻 dump，
   只拿到 **6 个元素**（只有窗口外壳），会让人误判"WebView 内容没暴露"。
   等 ~1s 再 dump 就有 **106 个元素**，中文标签齐全。**别因为在场就拿结论。**
2. **窗口位置会在两次调用之间漂移**（540,229 → 877,313 → 787,312，同一进程同一窗口）。
   同一批次里连测三次是稳定的。⇒ 坐标点击必须"**测量与点击在同一次调用里**"。
3. **`screencapture -R` 的几何从 `winlist` 第 7 列取**（列序是 `z win layer pid owner name bounds size`）；
   更稳的是 `-l <winlist 第 2 列>` 按窗口号抓，直接免掉坐标换算。
4. **读 PNG 时注意预览是缩放过的。** 1480 宽的图渲染成 1080，倍率 1.370。
   按渲染尺寸估的坐标会**偏 ~80px**，正好把一次点击从「命中 ×」推成「没反应」。
5. **标签的 × 不在 AX 树里。** 它是 `<span class="nx-tab-close">`，默认 `display:none`，
   激活/悬停才 `inline-flex`；WebKit 不把它暴露成可访问节点。只能算坐标点：
   `标签右边缘 − 8px（padding-right） − 8px（16px 宽的一半）`。
6. **`press` 是"命中即全按"。** 它按 `title|desc|value` 子串匹配，会把**所有**命中项都按一遍
   （`查看日志` 命中 2 个，输出了两行 `press -> AXError 0`）。按之前先看命中数。

## 七、未验证边界（如实标注）

- **Windows 桌面端未测**：本机是 macOS，无法本地验证。交叉编译 + CI 是唯一路径，本轮没做。
- **服务端形态（懒猫盒子）另有一路**：见同期盒子验收记录；两条路径的结论不可互相替代。
- 断言 ③ 用的是**前端返回**这一条路径；服务端 5s 宽限回收在桌面上**没有对应钩子**，
  所以它在桌上"不适用"，而不是"没验过"。
- 断言 ② 只证明了桌面形态下徽章不出现；服务端形态下"同档案两页 subscribers=2 / viewers=1"
  的对照由盒子那一路覆盖。
