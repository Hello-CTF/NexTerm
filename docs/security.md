# 安全说明

**中文** | [English](security.en.md) · [返回 README](../README.md)

## 同步加密的范围

同步对象在客户端用账号的数据密钥加密后上传，数据密钥再由账号密码派生的密钥加密保存在服务端；服务端只保存密文、不持久化明文，数据库或备份泄露时不会直接暴露明文，但弱密码仍可能被离线猜出。

这不是端到端加密：登录时密码会发送给服务端，服务端运营者或能截获登录请求的人可以据此解开同步数据。请只登录你信任的服务端，并通过 HTTPS 连接。

## 凭据保存

- 桌面和移动端使用保护密码或系统级保护（DPAPI / Keychain），移动端支持生物识别，支持空闲自动锁定。保护密码只用于本机解锁，忘记后已保存的凭据无法恢复。
- 浏览器模式的凭据由服务端 master key 保护的凭据库加密，服务端可以解密以建立连接。请备份 `/etc/nexterm/master.key`。

## 更新签名

桌面版安装更新前验证 `SHA256SUMS` 的 Minisign 签名并按它校验安装包；设备代理自升级同样验证 Minisign 签名，未内置签名公钥的开发构建会拒绝自升级。Windows 安装包没有 Authenticode 代码签名。

## 服务端

- `--auth off` 会关闭账号、管理与设备路由，任何能连到监听地址的人都能操作服务端，不能用于公网。
- 多用户服务端不在服务器本机上替账号执行命令或读取服务器文件，反向代理与 `X-Forwarded-For` 的信任规则、登录限流的范围见[服务端部署说明](../deploy/systemd/README.md)。
- VNC 服务器不提供 X.509 TLS 时连接不加密，建议经 SSH 主机中转；RDP 和 VNC 的 TLS 证书在首次确认指纹后固定。
- RDP 默认只接受 TLS 1.2 及以上；只有在资产中开启“允许旧版 TLS（1.0/1.1）”时才接受 TLS 1.0/1.1，供无法升级的旧主机使用，此类连接在审计日志中标记 legacyTLS。
