## 它做了什么

注入后会给页面打三个钩子（`installFilePickerHooks` / `installFileInputHooks` /
`installDownloadAnchorHooks`），把浏览器**原生文件入口**换成带「网盘文件 / 本地文件」
两个页签的统一窗口：

| 被拦的入口 | 选「网盘」时 | 选「本地」时 |
|---|---|---|
| `<input type="file">` 的 `click()` | 用 `DataTransfer` 回填 `input.files` 并派发 `input`/`change` | 走原生选择器 |
| `showOpenFilePicker()` | 返回网盘文件句柄 | 走原生 |
| `showSaveFilePicker()` | 返回网盘写入句柄 | 走原生 |
| 带 `download` 的 `blob:` / `data:` 锚点 | 走网盘保存 | 走原生下载 |

**判据是「页面上有没有可拦的原生入口」**，而不是「有没有上传下载功能」。
所以前端必须真的走原生 API（见 `src/ipc/webFiles.ts` 的文件头）——
自绘一个选择窗口再"接网盘"是拦不到的。

不覆盖：目录选择、浏览器接管的普通 HTTP 下载、应用自己发的 `fetch` / `PUT`。
